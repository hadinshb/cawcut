# Frame-aware motion direction

## Start with the current recording

Inspect the actual frame before choosing a palette or placing graphics. Measure the app window, active UI and webcam bubble if present. Keep the face and important controls unobstructed. Do not assume a fixed corner, resolution, screenshot or personal desktop layout. If no recording/reference exists yet, request one or label the initial design as provisional.

The user's current prompt and references define the palette, visual style, typography, object types and count. There is no fixed palette, logo theme, card style or object library required by Cawcut. Preserve actual logo assets if supplied. Record selected colors/styles in that video's own project, not as new toolkit defaults.

If the request leaves aesthetics open, inspect the footage and propose a coherent design based on readability and available space. Present that proposal for approval instead of requiring the user to invent every detail. An explicit requested style takes precedence over inferred colors from the footage; solve any contrast conflict visibly in the proposal.

## Graphics explain the edit

Choose visual objects that serve the current request and transcript. A waveform, repeated sentence strips, editable timeline or measured duration comparison are possible examples, not compulsory objects or reusable output to stamp onto every video. Use current results; no fabricated quality scores, saved-hours metrics or absolute automation badges.

Honor the requested count and scope. If unspecified, propose a small set of meaningful beats with one dominant graphic at a time. Preserve breathing room and reveal the original footage between beats. Avoid needless overlays. Real operation timers must be distinguishable from video playback time.

Choose local readable fonts where possible unless the user requests another font, and record the choice. Match motion to the requested style and keep it readable. A deliberate opaque inset/takeover is allowed when it serves the brief; label it and respect the requested webcam treatment.

## Storyboard and review

1. Identify spoken anchors from the approved EDITED transcript and source-to-edit mapping.
2. Show a concise table of graphic, anchor, start/end, placement and purpose.
3. Show representative composite proof frames on the real footage; a graphic on an empty background does not prove placement.
4. Check essential labels at 640 px and 320 px preview widths. Drop tiny metadata rather than making unreadable paragraphs.
5. Wait for design approval, then render sources into versioned outputs.

Measure actual alpha and verify a Final Cut-compatible transparent format, frame rate, color tags and placement. Keep audio unchanged. Inspect entrance, hold and exit; render a composite preview. Maintain per-video editable source and keep approved source clips separate in the new FCP timeline version.

Use HyperFrames guidance in the context of this brief. Generic decoration or layout recipes must not override the user's frame, readability or requested scope.
