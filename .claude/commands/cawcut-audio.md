## Contract and authorized delivery

Tune ONLY Final Cut Pro's native Voice Isolation Amount and Volume gain. Loudness must be OFF in the audition and delivered dialogue. Do not add EQ, Noise Removal, Hum Removal, gates, compressors, limiters, third-party effects, paid APIs or external audio processing. Local extraction/decoding and read-only analysis are allowed; do not bake cleaned audio into replacement media. These controls cannot guarantee studio sound or perfectly uniform dynamics.

Invoking this workflow authorizes ONE clearly named audition project and ONE new polished version derived from the actual target project after a usable native export is supplied. Explain these two projects before import; never modify the original project, silently add more variants/projects or delete the audition. Reuse an existing matching audition/export on resume. Additional rounds need the user's choice. The normal workflow asks the user for ONE native audio export, not separate exports for every candidate or manual slider testing.

## 1. Establish and preserve the current project

Identify the intended Library/event/project and dialogue recording/components. Ask only if ambiguous. Use the latest XML matching the actual Final Cut edit; do not use an old cut or flatten the rendered MP4. If current state cannot be accessed/exported, request File > Export XML once with exact instructions. Preserve a recoverable baseline XML and source hashes. Do not quit Final Cut unnecessarily, patch the app or edit the Library database.

Inspect media provenance and existing processing. Use the original linked dialogue, not an already enhanced export as source; previously baked processing cannot be undone. Replace existing Voice Isolation/Volume settings instead of stacking them, and disable/remove native Loudness on the scoped dialogue. Report unrelated existing dialogue processors: do not silently remove them or claim a two-control-only result while leaving them active; ask for permission to bypass/remove them if needed. Preserve intentional volume automation as a relative envelope with one gain stage, or ask if it conflicts with a uniform gain. Do not alter music, SFX, other speakers or different recordings silently.

## 2. Check the actual native setting route

Inspect live MCP schemas and the installed Final Cut DTD. Prefer a supported native action; otherwise make minimal component-level XML changes using `adjust-voiceIsolation amount="..."` and `adjust-volume amount="...dB"`. Respect `audio-channel-source`/`audio-role-source` placement, element order, channel routing, existing fades and handles. Verify percent units/ranges through current documentation or a real Final Cut export, not CDATA or private strength scaling. Ensure Loudness is off, gain is not doubled and Voice Isolation is not applied to duplicate simultaneous dialogue components. Validate XML and read back imported settings where possible. If checkbox state cannot be proved, request a single Inspector confirmation and label it unverified until confirmed.

Never claim the MCP/ffmpeg proxy runs Apple's Voice Isolation. Only actual Final Cut playback/export provides processed candidates. Do not install a UI bridge or promise automated native export without a verified supported route.

## 3. Build ONE audition reel from ONE passage

Choose a contiguous representative 10–15 second passage in the EDITED timeline, including quiet/loud speech, body, /s/, /f/, /sh/ and a real breath/pause/noise window where possible. If no suitable pause exists, disclose that noise assessment is limited; do not manufacture it. Use the exact same content and duration for every candidate. Keep this passage's clip boundaries/fades and source offsets; it may cross original clip boundaries. Exclude music/SFX from the audition only, without altering their final-project settings.

Measure the source to guide candidate coverage. Usually build 7 candidates: a Voice Isolation-OFF reference plus four increasing positive strengths at one common safe Volume, then two gain variants at the same middle isolation strength. An initial strength grid such as 20/40/60/80 is a search range, NOT a best preset; adapt and log it for this recording. Pick the common safe gain from available peak/headroom measurements (0 dB is valid), and choose the extra gain variants conservatively. Never assume an extreme or +12 dB is safe. If source clipping exists, flag it rather than claiming these controls repair it.

Keep Loudness off for ALL candidates, including the reference. Change one variable at a time: isolation comparisons share Volume; volume comparisons share isolation. Separate copies with frame-exact 1-second silent gaps and label each candidate with timeline markers, not spoken labels. Save `work/<recording>/native-audio-audition.json` containing baseline identity/hash, fps, passage source/edit mapping, candidate IDs, exact output frame/sample windows, settings, speech/pause/consonant windows and assumptions. Gaps are intentional; don't shorten them in analysis or use proxies with different timing.

Validate/import the reel into the chosen Library/event; verify candidate settings without claiming rendered quality. Show a concise English candidate table. Ask the user to export the WHOLE reel via File > Share > Export File > Audio Only > WAV (prefer 48 kHz lossless), to `out/<recording>/fcp-export/`, without normalization or extra processing. Say WAITING FOR NATIVE AUDITION EXPORT and STOP until the file arrives. Listening feedback is welcome but not required to start analysis.

## 4. Analyze the real native export and select settings

Check format, duration, candidate order and exact windows against the manifest; an ordinary project export, missing variant or proxy is not valid audition evidence. If the export doesn't match, explain the specific issue and do not apply a guessed winner. Preserve the export and raw measurements.

Measure per candidate: speech loudness (LUFS when the window supports it), true peak, pause RMS/noise and speech-to-pause ratio. Treat breaths separately from room hiss. Compare isolation candidates at approximately matched speech loudness in the ANALYSIS (gain-adjusted metrics; do not rewrite the audition audio); louder must not win by default. Compare aligned consonant/voice-body windows and transcript retention as warning indicators. These are imperfect proxies: recognition errors, spectral energy and noise scores do not prove naturalness or absence of watery/metallic artifacts.

Use an explicit documented ranking: reject clipping, clear loss of words/consonants or suspicious over-suppression; among acceptable candidates choose the lowest isolation with useful noise reduction before diminishing returns. Report ties and weak evidence. Select a measured provisional winner automatically when evidence is adequate, but label it MEASUREMENT-SELECTED, LISTENING UNVERIFIED unless heard and approved. If evidence cannot distinguish candidates safely, report INCONCLUSIVE and request one listening choice instead of inventing precision. Do not pick maximum isolation or minimum pause noise automatically.

Calculate final Volume from the chosen PROCESSED candidate: `delta_dB = min(target_LUFS - measured_LUFS, true_peak_ceiling_dBTP - measured_true_peak_dBTP)`, then `final_gain = candidate_gain + delta_dB`, accounting for the existing envelope and supported gain range. Use the user's target; otherwise document a conservative dialogue target and headroom policy, not a universal platform rule. If peak limits prevent target loudness, accept the quieter level and disclose the limit; do not add a limiter or Loudness. Candidate gain tests verify behavior, not an obligation to choose exactly one tested gain. Allow extra safety headroom for untested louder passages and AAC export overshoot. Sample-based headroom cannot certify the full project.

## 5. Automatically deliver ONE new full project version

Once a usable native audition export has been analyzed, apply the selected Voice Isolation and Volume automatically to the scoped dialogue in a new full project version, with Loudness off. No separate manual number-entry step is required. If the actual target project changed after the baseline (new graphics, cuts, SFX or manual changes), refresh its current XML first and merge only the audio changes; never overwrite newer work with the stored baseline.

Preserve full duration, original-media clip links, edits, graphics, SFX/music, markers, channel routing, synchronization and intentional fades/automation. Do not import the audition as the final project or replace dialogue with the audition export. Validate against the installed DTD; compare non-dialogue content with the refreshed baseline; import via the verified bridge and independently confirm the project and stored settings. Do not modify/delete the original project or Library database.

Save `work/<recording>/native-audio-report.md` (a short pointer may be placed at `work/native-audio-report.md`): baseline, audition/export identities, actual measured table, selection rule/confidence, chosen percentage/gain, proof of Loudness off, gain/checkbox verification, final project/XML, preservation checks and remaining limitations. Never overwrite another recording's report. Report APPLIED only for verified settings, not guaranteed best sound. Ask the user to listen once to the finished version and offer ONE full-project native export for recommended final quality control; do not request an export per clip. The audition export selects settings, whereas the full-project export checks generalization, loudest passages and residual noise across the whole edit. Until this full evidence exists, mark FULL-PROJECT AUDIO QC UNVERIFIED. Request it explicitly if suspected clipping or processing artifacts make it necessary; distinguish the optional recommended final QC export from the one audition export required for selection.

For a supplied full-project export, verify its identity and timing, measure full loudness/true peak and analyze representative regions using the edited transcript/frame mapping. Inspect joins and louder/quieter/noisier passages; do not attribute music/SFX energy to dialogue or pretend that a mixed export contains isolated voice measurements. Prefer consistent Voice Isolation for the same recording and speaker. Correct Volume conservatively across the recording, or propose justified small region-level Volume corrections when a real level mismatch remains; do not randomize settings per clip. Change isolation by region only for a genuine change in noise/microphone conditions, with transition/listening checks. Report measured problems and proposed corrections; get approval before another refinement project/import, and preserve the current version. Naturalness remains unverified without listening, even after numerical full-project QC.
